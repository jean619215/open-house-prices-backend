TASK-002（實價登錄 ETL 匯入 pipeline）在進入開發前的測案審查（2026-06-16）發現多項 Blocker，已退回「需求確認中」。

**Why:** 測案中有算錯的期望值，正確實作會被誤判 FAIL，且有邏輯矛盾的 AC 條款，開發者無法依此實作。

**How to apply:** 未來審查 ETL / 單位換算相關測案時，務必親自重算所有數值期望值，不能假設 QA 算對。特別注意：
1. 坪/平方公尺換算：1坪 = 3.305785 m²，元/m² → 元/坪 需「乘以」3.305785，而非除以。
2. 民國年轉西元：民國年 + 1911 = 西元年。
3. 測案中寫死「執行當年」的期望值（如 TC-05 building_age=23 for 2026），跨年後自動失效，應改為動態描述。

**Blocker 問題清單：**
- TC-03：面積 19.997 應為 ≈19.995（66.10÷3.305785=19.9953）
- TC-03：單價 958780 應為 ≈958678（290000×3.305785=958677.65），差 102 元超出 ±1 元容差
- AC-07：公式 `÷3.305785×3.305785` 數學等於原值（無轉換效果），措辭嚴重誤導
- AC-10 vs AC-18：has_parking「否則 FALSE」與「欄位缺失存 NULL」邏輯矛盾，需三態定義
- TC-15：去重鍵實作時才定（需求方要求「實作時提案」），但 TC-15 卻要求驗證冪等性結果 N，矛盾
- TC-05：硬編碼 2026 年，跨年後失效
