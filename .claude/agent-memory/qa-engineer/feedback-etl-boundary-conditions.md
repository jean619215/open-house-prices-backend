ETL 任務 QA 必須涵蓋以下情境，否則容易在測案撰寫階段遺漏：

**1. 「存 NULL 不整筆失敗」要逐欄驗**
每一個需要格式轉換的欄位（日期、面積、單價、屋齡、有無車位）都要有獨立的缺值/異常值測案，確認該欄 NULL、其他欄位仍正常、程式不中止。

**2. 冪等性的判準要量化**
「重跑不重複寫入」要以查詢筆數 N 前後不變為判準，不能只說「程式不報錯」。需確認去重鍵（hash 或組合鍵）由開發提案後填回卡片。

**3. 空 CSV 與下載失敗要分開**
- 下載失敗（ConnectionError / HTTP 4xx/5xx）→ 非 0 exit code，ERROR log，不寫入。
- 下載成功但 CSV 無資料列 → exit code 0，WARNING log，不寫入（不能讓空檔案觸發寫入邏輯）。

**4. 寫入限縮範圍要正反面都驗**
台北市+新北市：正面驗 COUNT > 0；反面驗其他縣市 COUNT = 0。

**5. 必產出物（文件/清單）要驗「內容完整性」而非只驗「存在」**
欄位落差清單要明確列出三類（來源有表沒有、表有來源無、型別/單位不一致），QA 要逐項確認覆蓋度。

**6. 程式碼規範用指令驗，不靠肉眼**
- `ruff check` / `ruff format --check` exit code 判斷。
- `ruff check --select ANN` 驗 type hint；`ruff check --select D` 驗 docstring（需在 pyproject.toml 啟用 pydocstyle）。
- `grep -r "print(" etl/` 確認無 print。
- 所有指令前綴 `uv run` 與專案套件管理一致。

**7. 單位換算公式要獨立驗算，不能靠直覺**
- 平方公尺轉坪：÷ 3.305785（不是 × 3.305785）。
- 元/平方公尺轉元/坪：× 3.305785（不是 ÷ 3.305785）。
- 寫測案前必須用 python3 -c 或計算機確認期望值，精度要對得上 AC 容差；TASK-002 發現 TC-03 面積 19.997 應為 19.995（差 0.002 超 ±0.01）、單價 958780 應為 958678（差 102 超 ±1）。

**8. 冪等性測案要含反向驗證（新筆仍可寫入）**
只驗「重複筆不增加」不夠；必須同時驗「去重鍵不同的新筆在重跑後仍正常寫入」，避免實作誤用了清空再重寫的策略通過重複性驗收。

**9. 特殊邊界值要明確列出，不能只寫「格式異常」**
- 日期欄位的 `0000000`（7 碼但代表不詳）需明確列為轉 NULL 的邊界情境，與空字串並列。
- 有此類「格式合法但語意無效」的欄位，務必在 AC 和 TC 各補一條。

**10. 時間依賴型期望值必須動態計算**
- 凡測案期望值涉及「執行當年」（如屋齡 = 當年 − 建築年），不可寫死數字；改為「執行當年 − X 年」的動態描述，並說明驗證方式（如 `EXTRACT(YEAR FROM NOW())`）。

**11. BOOLEAN 多態（三態）欄位要明確定義每個態，不能只描述部分**
- 有「缺失 = NULL」與「無車位 = FALSE」兩種不同空狀態的 BOOLEAN 欄位，AC 必須列出 TRUE/FALSE/NULL 三態的觸發條件，且 AC 正常路徑與 AC 異常路徑要互相引用，確保邏輯一致。

**Why:** TASK-002 ETL 測案在第一輪撰寫後被 Senior Reviewer 以 5 個 Blocker 退回，問題集中在數值計算錯誤、公式方向錯誤、三態矛盾、去重鍵未定義、時間硬編碼五類。

**How to apply:** 每次有 ETL 類 TASK 進入需求確認階段，用此清單（11 點）checklist 比對草稿測案。重點審查：換算公式獨立驗算、BOOLEAN 三態完整定義、冪等性含反向驗證、特殊邊界值逐條列出、時間依賴值改動態描述。
